P1: 外部书源包验收改由 CI 执行 + JS 依赖源单列一层

按上一轮结论走方案 A：探测不在本机做，交给 GitHub Actions。
起因是本机网络无法可靠访问这批小说站的 HTTPS（详见下「二」），
本地筛出来的「死源」是假死，拿它做删除依据会误杀好源。

二、为什么本机探测不可信（实测记录）
═══════════════════════════════════════════════════════════

  www.booksky.cc（仓库里已知可用的源）
    DNS  → 172.247.243.186        正常
    TCP  → 443 连通                True
    TLS  → 服务端 0 字节就 RST     ECONNRESET，收到字节数 = 0
    HTTP → 301                    正常
    TLS 版本 1.0/1.1/1.2/1.3      全部失败
    不带 SNI / 换 UA / 直连 IP     全部失败
  对照组：
    baidu 200 / github 200 / jjwxc 200 / qidian 202  ← 全部正常

结论：TCP 通、TLS 被对端重置，且与版本/SNI/UA 无关，不是本机 TLS 栈问题
（curl 走 Schannel、node 走 OpenSSL，两者一样失败）。
这类「线路层拦截」只能换出口，本地无法修，所以改由 CI 执行。

三、JS 依赖源单列一层（score.js / freshness-audit.js）
═══════════════════════════════════════════════════════════

背景：全库 680 个源里 394 个用了 JS（@js / <js> / java.*），
但其中 30 个居然有实测结果（JS 只在发现页/封面，主链路能静态跑通）。
所以不能「有 JS 就降级」——那会把实测通过的源一起冤枉。

分层判据改成「状态」而非「有无 JS」：
  有实测结果                    → 照常按分数分层
  无实测 + 有 JS + 历史有 pass  → js-dependent, weight 260
  无实测 + 有 JS                → js-dependent, weight 200
  无实测 + 无 JS                → untestable, weight 90~120

另：js-dependent 层不打任何 CI-* 分组标签。测不出来是 CI 的能力边界，
不是源的毛病；打「搜索失效」就是冤枉它。

freshness-audit.js 预筛不再剔除 JS 源（PRE_FILTER_KEEP_JS，默认开）。
理由：若直接剔除，报告会显示「覆盖率 100%」却漏掉 116 个真实存在的源，
读者无法判断是没测还是不必测。保留后它们以「JS求值已禁用」计入失败原因，
这个原因名本身准确说明了问题归属，比静默剔除诚实。
实测预筛从「剔除 141 个」变成「剔除 25 个」（只留真死的）。

四、踩坑与修正
═══════════════════════════════════════════════════════════

grade() 加第二参数导致 repo-regression 挂 5 条：
  那几条断言用 /function grade\(v\)/ 从源码抠函数体、new Function 重建。
  改签名直接失效。改为模块级 _gradingSource 传递上下文，签名保持 grade(v)。
  但重建后的作用域里拿不到模块级变量，所以函数体内改用
  typeof _gradingSource === 'undefined' 探测，且 JS 判定逻辑必须内联，
  不能调用外部 isJsDependent()。改完 144/144 恢复。

import-compare.js 首版去重计数错误（报「2838 → 1489」）：
  因为 norm 抹掉 #fragment 后把同站变体合并了。实际 2838 条 URL 全唯一。
